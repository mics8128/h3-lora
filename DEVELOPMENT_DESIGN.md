# H3 complete conditioning and AI task interface design

Status: implementation contract, not a claim of implemented capability. No engine edits, builds, tests, or inference were performed for this design.

## 1. Scope and evidence

Implement the complete achievable native capability set, not merely remove input guards: mixed ordered references and first/last anchors; arbitrary timed image, clip, audio and paired audiovisual guides; continuation; latent encode/import/export/decode; initial-latent partial denoise; masks; pause/checkpoint/resume; and a small-model-friendly task interface. Python standard library owns durable orchestration; C owns tensors, layout, sampling and inference. No new ML framework, network server, tool-calling model, or replacement checkpoint is required for these mechanisms.

Observed seams:

- `h3.h` exposes `h3_params`, borrowed paths/references and synchronous `h3_generate`; first/last anchors are separate from ordered references.
- `h3_host.c:h3_layout_build` rejects mixed keyframes/references, accepts only endpoints, emits condition rows before reference rows, and advances the target cursor with references. Therefore deleting mutual-exclusion guards is insufficient: guides must be placed relative to the **final target origin**, not the pre-reference text origin.
- `h3_dit.h` already separates immutable condition rows, request preparation, forward evaluation and denoising. Packed video and audio conversion routines are available.
- `h3_sampler.c` owns run-local carried state, RES previous clean predictions, LCM evolving random seed and video-clock audio scaling. Current `h3_sampler_run` discards these on return. Latents alone cannot resume this solver exactly.
- Video encoder and AudioVAE already expose native latent structures. `h3_audio_vae.h` specifies normalized audio `[32,2,T]`, 32 kHz input and right-padding to 800-sample boundaries.
- `REF_COMPATIBILITY_RESEARCH.md` records upstream mixed conditioning evidence and checkpoint/quality limitations.

Pinned upstream implementation reference: [ComfyUI nodes, revision 7cebca52227c63b4180ceed448cbd7ad22903b6d](https://github.com/Comfy-Org/ComfyUI/blob/7cebca52227c63b4180ceed448cbd7ad22903b6d/comfy_extras/nodes_minimax_h3.py), especially `MiniMaxH3AddGuide`, and [packed layout](https://github.com/Comfy-Org/ComfyUI/blob/7cebca52227c63b4180ceed448cbd7ad22903b6d/comfy/ldm/minimax/model.py). This node accepts image/clip/audio at arbitrary positive or end-relative pixel frame indices, injects fixed condition rows, floors clip lengths to `17k+5`, and bounds audio by remaining target duration. Our planner must report these transforms rather than silently apply them. Port model coordinate and condition-augmentation equations from this pinned source; do not derive timing by linear interpolation of latent indices.

## 2. Semantic distinctions and capability reporting

Three distinct operations must remain visible:

1. **Reference**: ordered subject/style/motion/voice evidence with presentation labels; not a placement or copy guarantee.
2. **Guide**: fixed encoded condition rows at target times, reinjected each evaluation; target rows still denoise independently. First/last are guide conveniences, not pixel locks.
3. **Preserve/edit mask**: explicit sampling constraint on target latent values. Latent preservation still does not guarantee identical decoded pixels because VAE encoding/decoding is lossy and temporally coupled.

Expose `mechanism`, `availability`, and `quality_evidence` independently per profile/capability. Availability is `available`, `missing_model`, or `unsupported`; quality evidence is `unverified`, `smoke`, or a named recorded evaluation. Do not imply supported checkpoint training from compatible tensor shapes. Existing Ref2VA/Turbo image/audio smoke evidence does not validate mixed-guide adherence, editing, long continuation, voice identity or frame-exact anchors.

Achievable with existing appropriate H3 encoders/decoder/transformer: all native conditioning, latent and solver mechanisms in this design. A missing locally installed encoder/transformer is a concrete `missing_model` prerequisite, not a reason to omit its interface. FL2VA adapters cannot be silently applied to Ref2VA; mixed references select a Ref2VA target and require matching adapters. Specialized editing/continuation/distilled weights, if absent, block claims of checkpoint-specific quality, **not** the generic mechanism. No promise that downloading another model alone fixes quality. Exact source pixels/audio require an explicitly requested final media copy/mux operation; that is separate from generation and must be recorded as postprocessing, never disguised as model conditioning.

## 3. Core interfaces and ownership

Keep one synchronous native execution seam. Extend `h3_params` and migrate its default initializer and every initializer/caller together; this repository does not need an ABI shim. Existing first/last CLI flags lower to guides and disappear as separate internal execution paths.

Proposed public declarations in `h3.h` (names form the integration contract):

```c
typedef enum { H3_GUIDE_IMAGE, H3_GUIDE_CLIP,
               H3_GUIDE_AUDIO, H3_GUIDE_CLIP_AUDIO } h3_guide_kind;
typedef struct {
    h3_guide_kind kind;
    const char *path;
    const char *audio_path; /* paired replacement; null selects explicit media policy */
    int frame_index;        /* resolved nonnegative target pixel frame */
    int source_start_frame, source_frames;
    int include_embedded_audio;
} h3_guide;
/* h3_params gains guides/guide_count, initial_latent_path, mask_path,
   start_transition, resume_path, checkpoint_path, latent_output_path,
   and on_transition callback/control state. */
```

Use a typed execution request internally for operations `generate`, `encode`, `decode`, `resume`; CLI dispatches to public native entry points `h3_generate`, `h3_encode_media`, `h3_decode_latent`, `h3_resume`. `h3_encode_media` returns/export-writes a clean AV latent bundle with explicit absent-stream metadata; a generate request must resolve both target streams. `h3_decode_latent` rejects nonterminal/noisy states unless the caller explicitly asks for a diagnostic preview. Do not make Python synthesize, reshape, or denoise arrays.

Params are borrowed for the synchronous call; context owns prepared caches; result owns reported output metadata. New arrays and state allocate once per request or solver creation, not per denoise step. Overflow/shape/range validation occurs before GPU allocation. Structured error codes are added alongside the human `h3_last_error` message; errors carry a field path where applicable.

## 4. Mixed references and arbitrary timed guides

Canonical input is an ordered references list and an ordered guides list. References keep current CLI ordering and per-type presentation numbering; guides do not acquire `<Picture N>` labels or reorder reference ordinals. Preserve existing FL2VA endpoint text/vision presentation for legacy endpoint-only requests; mixed requests use Ref2VA presentation plus independent guide conditioning, matching upstream `ReferenceToVideo -> AddGuide`. Do not duplicate guide images as unordered references.

`h3_layout_spec` replaces endpoint-only keyframe indices with descriptors containing kind, resolved frame, encoded video shape, audio length and payload offsets. Build in two passes:

1. Validate all dimensions and compute reference span/target time origin using exactly existing reference span rules.
2. Emit text, guide condition segments in caller order, ordered reference segments, target audio and target video. Guide positions use final target origin plus the upstream pixel-frame-to-model-time mapping; clip rows use the upstream encoded clip frame spans. Audio uses the same origin/time offset and target canvas audio spatial axis. Segment payload offsets are explicit, not guessed from row totals.

Fixed guide video/audio rows never enter target noise initialization or solver output. Include all guide identities, placement, trims, resize/crop, audio pairing and tensor shapes in conditioning/layout/prepared-DiT cache keys. Cache keys must also distinguish model/adapters and target origin. A layout shape signature alone cannot distinguish guide timing.

Planner accepts negative end-relative frames but resolves them before C. Reject empty guides, out-of-range starts, overflow and contradictory overlapping guide content. Disjoint audiovisual streams at the same time may combine. Until a blending semantic is explicitly added, overlapping guides on the same stream are an error, not last-wins behavior. Images occupy a placement instant; clip/audio spans use their actual encoded duration.

Output frame count remains on `17k+5` at 24 fps. Clip length below five is an image only when the user requests that interpretation; otherwise return a repair proposal. Clip lengths floor to a valid length only under explicit normalization approval in prepare. Audio resamples to 32 kHz stereo and right-pads as required; overrun trim, cover crop, first-frame stretch and time rounding appear in plan transformations. Guides may use sub-two-second audio: reference audio training-policy limits must not accidentally be reused as guide shape restrictions.

## 5. Continuation and revision

`continue` creates a **new plan**, not a resume checkpoint. Input includes source job/output or registered video asset, selected tail duration/frame count, desired additional frames, audio mode (`condition`, `silent`, `discard`) and join mode (`new_segment`, `concatenated`). Resolve a valid tail clip, anchor it at frame zero of a target containing overlap plus new content, and optionally guide aligned tail audio. References can coexist. Show generated total frames, overlap, discarded generated overlap, final assembled length and join timestamp in prepare.

For concatenated output retain original source frames/audio up to the join and append the generated suffix after overlap; no hidden crossfade, source modification or claim of seamless continuity. Re-encoding, timestamp alignment, audio padding/trim and mux choices must be explicit. Source video may be arbitrarily long; model context is the bounded chosen tail. Extended generation duration beyond a profile's validated range requires an explicit experimental profile, not a silent long-context promise.

`revise` creates a child plan using source clean latents or encoded output, new prompt/references/guides, selected mask and partial-denoise transition. It is an edit and resets solver history. `resume` restores the exact stopped computation and forbids changed conditioning/profile/schedule. Those operations cannot share an ambiguous `continue=true` flag.

## 6. Latent format, initialization, masks and resumability

### Portable file contract

Use the implemented versioned native envelope: clean latent type5, solver state type4. This is not safetensors or a foreign-framework interchange claim. The latent64-byte header contains source_frames at byte48, temporal_mapping at56 and reserved zero at60; mapping0 is native/generated, mapping1 is encoder-linear endpoints and requires positive source_frames. Native temporal conversion is explicit, not implied by compatible counts. `h3_latent.c` owns checked lengths, shape/finite validation and atomic writes. Native F32 video/audio payloads have declared byte order. State type4 retains six arrays for the original samplers, including fixed preservation_noise, complete schedule/history/RNG and explicit mask-presence metadata; ER-SDE revision1 adds a seventh derivative-history array. Preserve regions follow the same fixed noise/clean trajectory at each stream's sigma and equal clean only at terminal zero; unmasked carried state remains authoritative. Clean-latent records plus pinned manifest identify normalization/channel order/model identity. Reject foreign files rather than dispatch by extension; future Comfy/safetensors conversion requires a separate verified adapter.

Video is `[24,T,H/16,W/16]`; audio is `[32,2,T40]`. Encoder temporal output must be explicitly transformed to the generation temporal convention when needed; `h3_video_encoder_latent_t` and `h3_video_latent_t` are different and must never be treated as interchangeable. Record source frame count and exact mapping. Import rejects incompatible normalization, dimensions, channels, missing metadata, nonfinite tensors, truncation and excessive sizes. Foreign Comfy latent files require an explicit documented conversion with verified scaling/layout; filename compatibility is not proof of tensor compatibility.

### Partial denoise

Canonical control is `start_transition` in the full resolved schedule, from zero through total transitions. A UI strength can lower to this integer, but prepare returns the chosen index and both sigmas. Starting from clean native latents uses each stream's own schedule: `x_s=(1-sigma_s)*clean + sigma_s*noise` with the engine's native rectified-flow convention, before the sampler's video-clock audio carrying transform. The full schedule and original step index remain intact; do not rebuild a shorter schedule with different sigmas. Starting at terminal zero is a decode-only operation. Fresh partial edits reset multistep history; that is not exact resume. An explicitly noisy imported latent must identify its sigma and cannot be silently re-noised as clean data.

### Masks

Mask convention is universal: **1 edits, 0 preserves**; finite weights in `[0,1]`. Support video spatiotemporal and audio temporal/channel masks separately; unspecified mask means all editable. Pixel masks lower to latent masks via one documented resize/time mapping, surfaced in prepare; native latent masks require exact broadcastable shapes. Initialize protected regions on their fixed preserve/noise trajectory before the first evaluation. After each completed solver proposal, project exactly once at that stream's next sigma: `m*proposal + (1-m)*preserve_trajectory`. Do not also preproject model clean predictions: that doubles the preservation effect for soft masks. RES previous-clean history retains raw model clean predictions in the same representation as its current prediction input; the committed carried state contains the projected proposal. Never draw fresh protection noise each step. Fully protected terminal latent values equal the clean preserve tensor; decoded pixel identity is not promised. Acceptance includes a one-step zero initial state, zero velocity, clean10,mask0.5 result5 (not7.5) for all three solvers, alongside fixed-trajectory and exact-resume cases. These are required checks, not results independently exercised by this design worker.

### Incremental solver and checkpoint

Use the concrete SamplerControls contract: opaque `h3_sampler_state`; `h3_sampler_config` contains kind, schedule by value, video/audio shifts, seed, `start_step`, video/audio counts and `request_digest[32]`. `h3_sampler_state_start(config,video,audio,video_clean,video_mask,audio_clean,audio_mask,error,size)` initializes state; `h3_sampler_state_run(state,stop_step,evaluate,...noise,...observe,...error,size)` advances to an absolute exclusive transition boundary. `h3_sampler_state_save/load`, `h3_sampler_state_free`, const video/audio getters and `h3_sampler_state_step` complete the interface. Clean tensors are required with masks; stateful persistence rejects external noise callbacks whose opaque random state cannot be serialized, while the legacy run wrapper retains callbacks. State owns preallocated workspace, next transition, dual-stream schedule, carried/scaled audio, RES history, LCM evolving RNG, masks and preservation trajectories. The serving Euler loop needs a parent-owned DiT bridge preserving its schedule semantics. Native `h3_latent` contains video_frames/height/width/audio_frames, counts and video/audio pointers, with init/free/save/load; its on-disk schema must still carry the metadata above rather than treating shape-only interchange as sufficient for foreign normalized latents.

A pause/cancel request is observed at completed transition boundaries, after all streams and history commit. Pause writes an atomic checkpoint before reporting `paused`; cancel reports `cancelled` and only keeps a checkpoint if explicitly requested. A failed write leaves the previous checkpoint valid and reports an error, never a falsely resumable state. Final publication occurs only after outputs are complete.

Exact computational resume requires matching model/adapters, conditioning, schedule, shapes, sampler/kernel configuration and execution implementation. Approximation modes (denoise reuse, core reuse, reduction, streaming) may carry cached velocities/core state. Either serialize all influential cache state or reject exact-resume preparation for that configuration; do not silently clear caches while claiming identity. Start with a profile explicitly selecting uncached exact mode for resumable tasks; implement support or an explicit capability rejection for each other mode. Same-device/same-build uninterrupted-vs-resumed equality is the acceptance target; cross-device/build bitwise determinism is not promised. Changed dependencies produce `checkpoint_incompatible` with exact differing fields.

Native resume must recompute execution identity from actual model/adapter and conditioning identities, target/layout, complete schedule, kernel/precision/environment configuration and build identity. A caller-supplied `request_digest` alone is not authentication of those values: combine or replace it with the native-derived digest and reject differences even if a raw CLI caller repeats the original supplied digest. Planner pinning of assets, profiles and the native binary supplements, but never replaces, this native check. Generation and encoded-media temporal cadence remain distinct; native import must validate or explicitly convert the mapping, not merely accept equal element counts.

## 7. Small-model task module

External entry point: `python3 tools/h3_tasks.py <operation> --json`, one JSON request on stdin and one JSON response on stdout; diagnostics go to stderr. A persistent stdio wrapper may reuse these same functions, but no HTTP stack is necessary. JSON never contains executable shell fragments. Call native CLI/FFmpeg with argument arrays, not shell interpolation. Task state root is explicit; stdlib SQLite stores assets/plans/jobs/events/idempotency, and immutable files store native inputs/outputs.

### Operations and invariants

- `capabilities`: installed model/profile inventory, schema version, native build identity, mechanism/availability/evidence, constraints, masks/resume support. Never advertise design-only capabilities as executable.
- `asset.register`: copy a readable local media/latent file to a content-addressed managed store, probe once, return opaque `asset_id`, digest, streams, dimensions, duration/frame rate and normalized metadata. Small-model requests use IDs only, not arbitrary runtime paths. Register pins bytes; later source edits cannot change plans. Reject nonregular/missing assets and incomplete latent schemas.
- `profiles`: return short stable IDs and explicit target/checkpoint/adapter digests, dimensions, schedule and exact/experimental properties. Use existing preset inventory where applicable; no hidden guessed Ref2VA training shifts. Version profiles; old plans retain a resolved snapshot.
- `prepare`: validate and normalize a task, resolve assets/profile, compute frame/timing/crop/audio policies, model prerequisites and compatibility, return immutable `plan_id`, digest, concise summary, resolved arguments, warnings and repairable errors. No inference or queue side effects. Requested intent and resolved execution are both preserved.
- `submit`: accept only `{plan_id, plan_digest, idempotency_key}`. Atomically insert job and idempotency record; the same key+plan returns the same job even after restart, different plan returns conflict. Recheck pinned dependencies before admission. A submit never silently reparses new mutable profiles.
- `inspect`: accept job or plan ID, return state, last phase/transition, output asset IDs, checkpoint ID, structured failure and explicit next valid operations. Bounded event pagination uses a sequence cursor, not unbounded logs.
- `revise` and `continue`: accept parent output/asset IDs and a constrained intent patch; return a new prepared immutable child plan. `resume` prepares a checkpoint continuation with no intent edits. `pause`/`cancel` request a state transition on a job; repeated requests are idempotent.

Minimal prepare example:

```json
{"operation":"prepare","task":{"prompt":"A person walks forward","profile":"ref-base-exact-v1","frames":124,"references":[{"asset_id":"a_person","role":"image"},{"asset_id":"a_voice","role":"audio"}],"guides":[{"asset_id":"a_start","kind":"image","frame":0}],"outputs":{"media":true,"latent":true},"normalization":"require_exact"}}
```

Normalization defaults to the administrator profile's immutable, versioned named policy, initially `standard_media_v1`; small-model callers need not enumerate codec flags. The profile pins aspect-preserving guide cover-crop (reference sizing remains its separate declared `match` policy), declared target-FPS resampling/rounding, audio32kHz stereo conversion and required right-padding. Prepare always lists actual operations with source/resolved dimensions, time/frame/sample changes and crop geometry; the policy identity/content participates in the plan digest, and submit of that digest approves precisely those resolved transformations. A caller can override with `require_exact`, which rejects every required transformation rather than silently ignoring the override, or choose a supported policy ID. Policy changes require a new version and new prepare, never reinterpret an existing plan. Semantic changes are excluded from `standard_media_v1`: audio/video overrun trimming, source subclip selection, reinterpreting a short clip as one image, shortening requested output, dropping a reference or requested guide frame/event, changing speech, and reducing native render resolution still require explicit intent/repair. Ordinary declared FPS resampling must disclose its mapping, but cannot erase a designated guide frame or requested event without a separate repair. Success returns `plan_id`, `plan_digest`, `resolved`, `summary`, `transformations`, `quality_evidence` and `warnings`. Missing-prerequisite plans remain inspectable but non-submittable; no partial execution follows validation failure. The small interface is profile plus optional strict override, not an accumulating list of low-level consent flags.

Repairable error shape:

```json
{"ok":false,"error":{"code":"guide_out_of_range","field":"task.guides[0].frame","message":"Guide begins outside the resolved target.","details":{"requested":130,"target_frames":124},"repairs":[{"operation":"prepare","patch":{"guides[0].frame":123}}],"retryable":false}}
```

Stable codes include `unknown_asset`, `invalid_request`, `normalization_required`, `guide_overlap`, `missing_model`, `profile_incompatible`, `latent_incompatible`, `checkpoint_incompatible`, `dependency_changed`, `idempotency_conflict`, `resource_busy`, `cancelled`, `engine_failed`, `output_failed`. Repairs are proposals requiring another prepare, never automatic fallbacks. Warnings do not repair invalid requests.

### Durable single-worker execution

Use a single admitted native process per device. Transactional claim/worker lease prevents duplicate launches; durable job states are `queued`, `running`, `pausing`, `paused`, `cancelling`, `cancelled`, `succeeded`, `failed`, `interrupted`. Worker restart marks orphan runs interrupted, never restarts expensive sampling automatically. Expose explicit resume/retry options only when artifacts support them. Job idempotency prevents duplicate jobs, not a false exactly-once guarantee across a process crash.

Native CLI accepts a canonical machine execution manifest and emits versioned JSONL progress/result/error events. The manifest is generated by the planner from pinned paths and validated again natively; C parses a constrained JSON schema, not general model-authored prose. Native capability probing is machine-readable. Do not scrape terminal spinner output. Small model sees profile IDs, assets, placements and repair messages; backend resolves dozens of speed/kernel flags.

## 8. Implementation ordering and handoff contract

All steps are part of the deliverable; ordering is dependency management, not a reduced first-phase scope.

1. Freeze native guide/layout descriptors, latent schema, machine manifest and task JSON examples with the integration owner. Pin upstream equations and baseline fixture outputs before changing endpoint behavior.
2. Implement two-pass mixed layout, image/clip/audio guide encoding and fixed condition-row packing. Migrate first/last callers. Include cache identities and model/adapters validation in this same cutover.
3. Implement native latent I/O and encode/decode operations, explicit generation/encoder temporal mapping, then initial-latent partial denoise and masks.
4. Refactor both sampling paths into transition-state execution and implement checkpoint import/export/control. Resolve approximation-cache support explicitly; never declare global resumability from Euler-only support.
5. Implement native JSON manifest/events/capabilities. Python assets/profiles/prepare/inspect can develop concurrently against frozen fixtures; submit/revise/continue/resume integrate only with actual reported capabilities.
6. Finish continuation assembly, transactional jobs/idempotence, interruption recovery and every negative path. Update docs and inventories to describe actual mechanism availability, installed prerequisites and observed evidence.
7. Main integration owner runs the acceptance matrix once in an isolated workspace after all edits land. No worker runs builds/tests/inference midflight. Existing deployed source and running jobs remain untouched.

No new testing result may be recorded by this design. Missing weights must be reported by exact role/profile/path/digest requirement and separated from unfinished implementation; no fake-success capability or placeholder output is acceptable.

## 11. Quality-first revision: acceleration claims are not a quality strategy

This section supersedes any interpretation that implementing more controls, rendering more pixels, or stacking fast settings by itself repairs the user's unsatisfactory output. The user reports poor quality; that observation is accepted. The exact complained clip has not been identified, so a remotely inspected recent job is a **candidate**, not a confirmed reproduction. No new generation, timing measurement or perceptual evaluation was performed for this revision.

### Historical machine-route regression found and resolved during integration

At this inspection, `h3_manifest.c` **unconditionally assigns `p.on_transition=transition`**, even when no control file is supplied. `h3.c` chooses controlled sampling whenever initial_latent_path, resume_path, checkpoint_path **or any on_transition callback** is non-null. The Python worker also always supplies a control path and checkpoint path. Consequently a normal machine/task generate call enters controlled CPU-orchestrated sampling and requires full layers/reuse1/no reduction/no SSD, whereas an ordinary human CLI call with no controlled options still reaches the existing serving-Euler GPU path. That is a real route-selection change, not proof of a measured slowdown. For simple Turbo, host orchestration already existed, but extra persistent arrays, identity checks, copies and final checkpoint I/O still need measurement; do not claim it is costless.

“Uncached exact” here means supported solver-state reproducibility with approximation caches disabled; it does **not** mean all-BF16 computation, pixel-identical source preservation, a universally higher-quality sampler, or faster inference. Existing M5 INT8 weight/projection choices are separate numerical controls. CPU orchestration and exact replay are likewise separate from official checkpoint quality.

### Remaining AI worker residency cost
